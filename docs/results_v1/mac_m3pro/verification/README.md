## V2 TEAM 19（case2F）: 計算した共振と実測の比較

- 方法: `matrix_features.py --backend mumps --open-modes`（開放系の共振の探索。B5 では既定で飛ばした）で、運転点（実測の共振周波数 \(f_0\)）の近くの離散系のモード \(k\) を求め、\(f=\operatorname{Re}k/k_0\cdot f_0\)、\(Q=\operatorname{Re}k/(2\lvert\operatorname{Im}k\rvert)\)。出力 `case2F_*.json`（`resonance.modes_near_k0`）。
- 結果（運転点の近くの curl を持つモード、MHz（Q））:

| セット | 実測 \(f_0\) | 計算したモード |
|---|---:|---|
| empty | 2541 | 2022（8）、2490（4）、**2519（839）**、2536（23）、2624（139）、3073（54）、3152（612） |
| plex7 | 2490 | 1931（54）、2193（4）、2556（27）、**2600（1324）**、2799（1）、3041（6）、3229（1307） |
| plex9 | 2462 | 1959（6）、2022（6）、2610（22）、2635（5）、2645（3）、3148（145） |
| pvc7 | 2482 | 1779（17）、1868（3）、2476（13）、2557（41）、2583（8）、3105（37） |
| pvc9 | 2446 | 1911（4）、1937（4）、2388（6）、2489（9）、2576（27）、3058（40） |

- 所見: 空の空洞では Q の高いモード 2519 MHz（Q 839）が実測と −0.9% だが、誘電体棒を入れた4セットでは実測に対応するモードを特定できない（Q の高いモードは plex7 の 2600 MHz（+4.4%、棒を入れると共振は下がるはずなのに上がる）だけで、他は Q 3〜40 の放射に近いモード）。ベンチマークのメッシュは粗く（PPW 約7、自由な辺 1,784〜1,952、セットごとに λ0 で縮尺した別のメッシュ）、励振は実験の導波管給電ではなくガウス型の体積電流である。
- **結論: ベンチマークの case2F は「TEAM 19 の形状と材料を使い、実測の共振周波数で解く問題」であり、実測と照合した問題ではない**。`problem_settings.md` の「実測検証済み」はこの記録では裏付けられない。論文では照合したとは書かない（2026-10-14 利用者が決定。outline.md 4.1）。

## V4 メモリ（最大 RSS）の取りこぼし

- 原因: ランナー（`freefem/run_benchmark.py` の `watch_rss`）は FreeFEM のプロセスの最大フットプリント（macOS: `ri_lifetime_max_phys_footprint`）を **1秒おき**に読む。1秒前後で終わるジョブは、読む前に終わるか、読んだ時点の値が最大より小さい。
- 影響: v1.0 の 1,344 件のうち、メモリが 0 のジョブ 52 件（case2F の全組合せなど）、合計時間 3 秒未満のジョブ 83 件（20 セット: case2E、case2F、P05 の多く、P01-1_coarse、case3D:sparse_array）。
- 論文での扱い（案）: メモリの比較（outline.md 図4）は合計時間が数秒以上のジョブに限り、取り方（1秒おき）を5章に書く。ランナーを直して流し直すことはしない（時間・反復数には影響しない）。
