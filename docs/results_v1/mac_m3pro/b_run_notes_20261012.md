## 2. 途中で起きたことと対処

1. **ふたを閉じたスリープ（10/5 17:32〜10/6 08:40）**: `caffeinate -i` はふたを閉じたスリープを防がない。その間の iter の結果（124件: `host suspended` 12件、MPI の終了処理の失敗による `error` 94件、時間の信用できない収束など）は `results/pcb_v1_discard_20261005_sleep/` に退避し、iter を最初からやり直した。MUMPS（17:29 までに完了）はそのまま使った。`v1.sh` にスリープが無効でないときの警告を追加。
2. **P07-4 accel_ic/gmres の `error`**: 計算は10,000反復まで終わっていたが、MPI_Finalize が `OFI poll failed (nic=en0)` で失敗（ネットワークの変化と重なった）。単独で流し直し、`max_it`（相対残差 2.83e-2、元と同じ）。
3. **参照解の取り違え（ランナーの不具合）**: `run_pcb_benchmark.py` が参照解をジョブ名（セット名）と組合せの組で引いていたため、セット名が同じ既存のケース（standard: case1A と case2A、off_resonance: case2A〜2D）で、最後のケースの参照解が使われていた。収束したのに誤差がない37件が出た。キーにケース名を加えて直し（`regress` 11/11 PASS）、影響した4セット×11＝44件を流し直した。ソルバーの計算には影響しない。

## 3. B6 の残り：既存ケースのメッシュ収束（2026-10-12）

- 対象: 既存の Core 4セット。lc（`lc*`）に倍率 s = 1、0.8、0.63、0.5 を掛けたメッシュ（s = 1 は B1 のメッシュ、MD5 一致）。s ≥ 0.63 は `mumps/direct`、s = 0.5（62万〜72万自由度、MUMPS は 18 GB に収まらない）は `npatch_asm/cocg`（rtol 1e-8、4件とも収束、case3A は 33,358 反復・約1.5時間）。手順は [pcb_usage.md](../../pcb_usage.md) 4.7節、表は [mesh_convergence.md](mesh_convergence.md)。
- 比べ方: 粗い解とその curl を最も細かいメッシュの求積点で直接評価して差を積分する（`pcb_mesh_convergence.edp`）。メッシュが入れ子でないので2つの離散化誤差はほぼ無相関で、差は \(d(s)^2 = C^2(s^{2p}+0.5^{2p})\) に従う（滑らかな場の補間で確認: 0.0615 と 0.0307 に対し差 0.0686）。最初は入れ子のメッシュの式 \(C(s^p-0.5^p)\) で当てはめて次数が下限に張り付いたので、式を直した。

| セット | s = 1 の H(curl) 誤差の推定 | 次数 p | 備考 |
|---|---:|---:|---|
| case2A:off_resonance | 6.4% | 1.03 | 滑らかな場の補間誤差（6.1%、同じメッシュ）とほぼ同じ。汚染はほとんどない |
| case2A:standard | 18% | 1.08 | 共振（0.8% 離れ）の近くで、同じ空洞の off_resonance の約3倍 |
| case1A:standard | 30% | 1.02 | PEC 球の散乱、UPML を除いた領域でも 29% |
| case3A:high_contrast | 37%（L2 は 63%） | 1.65（L2 0.60） | κ = 100 の誘電体。当てはめが悪い（残差 0.05）、漸近域に入っていない |

- 所見: ベンチマークのメッシュ（lc = λ/8、平均の辺 約 λ/6）では、最低次の Nédélec 要素の H(curl) 誤差は 6〜40% で、3セットは1次で収束している。反復法の停止（相対残差 1e-8、MUMPS に対する差 1e-6 以下、1章）は離散化誤差より5桁以上小さい。ベンチマークは「与えられた離散系を解く速さ」を比べるもので、物理量の精度を示すものではないことを論文に書く（PPW を上げると系が大きく、共振の近さも変わる）。

## 4. B5 の途中経過（2026-10-13）

- 特徴量（`chains/b5.sh`）は 57/112 セットまで進んだところで、開放系の共振モードの探索（`resonance()`）が律速になった。curl を持つモードが見つかるまで固有値を 120 個まで広げ、開始ベクトル2本で探すため、30万自由度級では数時間かかる（P01-1_t は 6.8時間のうち 6.7時間、P06-L0 は 7時間を超えても終わらず）。旧結果（v1.0 より前）では同じセットで 38〜126秒だったが、値も違った（P01-1_fine の共振までの距離 0.67 → 0.90）。開放系では探索が安定しない。
- 開放系の共振の値は表に出していない（`summarize_matrix_features.py`）ので、開放系では探索を飛ばすことにした（`matrix_features.py`、既定。`--open-modes` で従来どおり）。P06-L0 を止め、チェーンを最初から再開した（済みの57件は飛ばす）。済みの57件のうち開放系のものには共振の値が入っているが、表には使わない。
- 同じセット（P05-1）を2回計算した特徴量の差は丸め誤差（約 1e-15）だけだった。

### 5.1 所見（順位相関はすべて Spearman、反復数は収束した組合せだけ）

1. **前処理は2群に分かれる（Core 9セットの所見（matrix_features.md 8.3節）が112セットで成り立つ）。** cslp・cslp_hx は `kappa_ritz` の中央値 3.9・7.5、`origin_sep` > 0 が 100/112・96/112、300ステップで \(10^{-8}\) に達したのが 109/112。局所的な前処理（gs、ssor、amg_gamg、accel_ic）と npatch_asm は中央値 340〜1,500、`origin_sep` > 0 は 0/112、達したのは 0〜15件。hx は中間（220、4/112、58/112）。
2. **プローブの GMRES の残差（`probe_it`、届かなければ末尾50ステップの率による外挿 `extrap_it`）は、実際の反復数と順位がよく合う。** hx/gmres 0.99（93件）、ssor/gmres 0.85、gs/gmres 0.82、cslp_hx/gmres 0.80、npatch_asm/cocg 0.78、ssor/cocg 0.74、accel_ic/cocg 0.70、amg_gamg/cocg 0.65。Core だけの旧所見（外挿と GMRES の反復数で 0.34）より高いのは、112セットで難しさの幅（規模・周波数）が広がったためと考えられる（同じ幅の中での予測力は別に確かめる必要がある）。例外は cslp/gmres（0.22）。内側を厳密に解いた演算子と、標準の内側（GAMG を前処理にした GMRES、rtol \(10^{-2}\)）の差が大きい（旧所見の3と同じ）。
3. **`kappa_ritz` 単独では反復数を説明しない**（−0.54〜0.28）。
4. **行列の特徴量では、\(k_0\) 未満のモード数（`modes_below_k0`）が HX 系・npatch の反復数とよく合う**: hx/gmres 0.84、cslp_hx/gmres 0.77、npatch_asm/cocg 0.70。ssor/cocg とは合わない（0.07。こちらは規模 n・N_grad と 0.57〜0.59）。閉じた系（42件）の共振までの距離は npatch_asm/cocg と −0.82、ssor/cocg と −0.58。\(\kappa_2\) はどれとも弱い（−0.41〜0.42）。
- 注意: 反復数は収束したものだけで、打ち切り（`max_it`）は除いた。難しいセットが落ちるので相関は偏りうる。論文1の分析（paper_plan D）では打ち切りを含めた扱い（順位の下限など）を決める。
